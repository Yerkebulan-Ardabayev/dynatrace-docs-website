Запускать ActiveGate на выделенной системе

Для оптимальной производительности и повышенной безопасности рекомендуется устанавливать и запускать ActiveGate на выделенной системе.
Использование ActiveGate на выделенной системе снижает риск компрометации данных аутентификации ActiveGate и уменьшает вероятность злонамеренного изменения конфигурации.

Подробные характеристики пропускной способности журналов на Environmental Active Gate при приёме журналов API описаны на странице [Log Monitoring default limits (Logs Classic)](/managed/analyze-explore-automate/log-monitoring/log-monitoring-limits "Лимиты по умолчанию для последней версии Log Monitoring в Dynatrace.").

## Требования к оборудованию

Необходима машина, выделенная для ActiveGate, со следующими характеристиками:

* 4 ГБ свободного места на диске для установки, настройки ActiveGate и Extensions, хранения журналов и целей автоматического обновления.
* 4 ГБ для кэшированных установщиков и образов контейнеров ActiveGate и OneAgent, если их потребуется хранить.
* Место для файлов дампов, если их потребуется хранить. По умолчанию эта функция отключена, но её можно включить в конфигурации ActiveGate. Максимальный размер хранилища [настраивается](/managed/observe/application-observability/profiling-and-optimization/memory-dump-analysis/configure-an-activegate-for-memory-dump-storage "Как включить хранение дампов памяти на ActiveGate."), по умолчанию составляет 100 ГБ.
* 600 МБ + 1,5 ГБ (буфер) свободного места на диске для файла сохранения повторной передачи журналов Extension Execution Controller.
* Место для загружаемых расширений, в зависимости от используемых расширений.
* 2 ГБ ОЗУ (рекомендуется 4 ГБ).
* 1 двухъядерный процессор.

В крупных средах может потребоваться машина с дополнительными ресурсами процессора и памяти.

## Подробности о сохранении данных

Механизм надёжности обеспечивает сохранность журналов Extension Execution Controller (EEC) в случае недоступности ActiveGate или OneAgent, проблем с сетью или перегрузки EEC при приёме данных. Это позволяет минимизировать пробелы в покрытии журналами.

### Общая информация

* Для постоянного хранения данных требуется 2136 МБ свободного места на диске:

  + 600 МБ свободного места для использования механизмом надёжности
  + 1,5 ГБ свободного места в качестве буфера
* Выполнение требования проверяется периодически, и если оно не выполнено, сохранение будет отключено, а передача журналов будет осуществляться без механизма надёжности.
* Объём используется пропорционально нагрузке при приёме журналов.
* Если требование невозможно выполнить на хосте, можно изменить конфигурацию сохранения журналов. Подробнее см. в разделе [Конфигурация сохранения данных](#persistence_config).

### Конфигурация

Файл конфигурации для Windows: `C:\ProgramData\dynatrace\remotepluginmodule\agent\conf\extensionsuser.conf`

Файл конфигурации для Linux: `/var/lib/dynatrace/remotepluginmodule/agent/conf/extensionsuser.conf`

| **Переменная** | **Описание** |
| --- | --- |
| `persistence.reliable_mode` | `true`, надёжный режим включён; SFM-журналы формируются при невыполнении требования к пространству `false`, надёжный режим отключён; передача журналов осуществляется без механизма надёжности |
| `persistence.total_limit_kb` | Максимальный предел объёма для Log Persistence Extensions в килобайтах. По умолчанию: 600 МБ. Можно изменить вручную, если требование невозможно выполнить на хосте. |

## Системные требования

* ActiveGate поддерживает только операционные системы на архитектуре x86-64 (64-разрядные Intel/AMD).
* Необходимо обеспечить корректную [конфигурацию сетевых портов](/managed/ingest-from/dynatrace-activegate/supported-connectivity-schemes-for-activegates "Приоритеты подключения между типами ActiveGate, а также между ActiveGate и OneAgent.").
* Установка ActiveGate не поддерживается на Windows с отключённой учётной записью `NT AUTHORITY\LocalService`.

## Руководство по выбору конфигурации

### Руководство по выбору конфигурации для маршрутизации трафика OneAgent

В следующей таблице представлены требования к размеру экземпляра машины в зависимости от числа агентов OneAgent, взаимодействующих с ActiveGate. На каждом хосте OneAgent выполняет восемь задач мониторинга:

* Мониторинг инфраструктуры
* Мониторинг журналов
* Full-stack мониторинг 3 экземпляров Apache Tomcat
* Full-stack мониторинг 2 экземпляров Apache HTTP Server
* Мониторинг расширений

Реальное число хостов может отличаться в зависимости от технологий, задействованных в вашей среде. Рекомендуется, чтобы загрузка CPU машины, на которой работает ActiveGate, не превышала 50%, а памяти, 80%. Кроме того, необходимо учитывать, что ActiveGate могут быть недоступны в период обновлений, перезапусков или кратковременных сбоев связи. Для обеспечения высокой доступности работающие ActiveGate должны быть способны принять трафик недоступных ActiveGate.

### Руководство по выбору размера для приёма логов API без дополнительной нагрузки

ActiveGate получает данные логов исключительно через API Log ingestion.

* Непрерывный приём логов выполняется при типичном распределении размеров сообщений.
* **Размеры сообщений**: 5% очень маленькие (1,5 КБ), 20% маленькие (1,5 КБ), 50% средние (2,2 КБ), 20% большие (3 КБ), 5% очень большие (7,8 КБ)
* **Количество атрибутов**: от 5 до 100 атрибутов на запись лога
* **Размеры батчей**: от 10 до 100 сообщений на вызов API

Приведённые конфигурации ресурсов обеспечивают запас для пиковых нагрузок и переключения реплик во время обновлений.

### Руководство по выбору размера для совмещённой нагрузки (маршрутизация OneAgent + приём логов API)

ActiveGate одновременно обрабатывает трафик маршрутизации OneAgent и приём логов API.

* Трафик маршрутизации OneAgent составляет 50% от пропускной способности только маршрутизации для данного размера машины (мониторинг инфраструктуры, мониторинг логов, full-stack monitoring, мониторинг расширений).
* Приём логов API выполняется параллельно при типичном распределении размеров сообщений.

Реальная пропускная способность зависит от конкретной конфигурации мониторинга, объёма логов, размеров сообщений и характеристик нагрузки. Загрузка CPU машины, на которой работает ActiveGate, не должна превышать 50%, а память, 80%. Во время обновлений, перезапусков или кратковременных сбоев связи ActiveGate могут быть недоступны. Для обеспечения высокой доступности оставшиеся ActiveGate должны быть способны принять трафик от недоступных ActiveGate.

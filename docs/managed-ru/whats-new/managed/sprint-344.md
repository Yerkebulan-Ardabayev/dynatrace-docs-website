Software Delivery

## Настраиваемые окна обновления и целевые версии для Environment ActiveGate

Автообновления Environment ActiveGate теперь предлагают те же параметры управления, что и OneAgent.

Можно выбрать целевую версию (**Latest stable**, **Previous stable**, **Older stable** или конкретную основную версию, при этом последняя подверсия применяется автоматически), выбрать один из трёх режимов обновления (**Automatic at earliest convenience**, **Automatic during update window** или **No automatic updates**) и использовать те же окна обновления, которые уже настроены для OneAgent.

Настройки на уровне отдельного ActiveGate могут переопределять значения по умолчанию для окружения, а для ActiveGates с ручным управлением отображается кнопка **Update now to target version**.

Эндпоинты Environment Deployment API `GET /api/v1/deployment/installer/gateway/{osType}/latest` и `GET /api/v1/deployment/installer/gateway/{osType}/latest/metainfo` тоже учитывают настроенную целевую версию, поэтому загрузки и метаданные установщика соответствуют выбранной версии ActiveGate в окружении.

### Улучшенные прогнозы DPS и события стоимости

[Cost monitors](/managed/manage-your-costs/control/cost-monitors "Узнайте, как использовать функцию Cost Monitors для создания прогнозов и событий стоимости.") теперь предоставляют более детальные сведения о затратах. Большинство значений не претерпят существенных изменений; отклонения возможны, хотя и редко, и основаны на фактических данных потребления DPS. При возникновении отклонения будет отправлено уведомление по электронной почте. После корректировки прогнозы становятся стабильными и согласованными.

Application Security | Vulnerabilities

### Выявление вредоносных пакетов в окружении с помощью Runtime Vulnerability Analytics

Охват обнаружения вредоносных пакетов в Dynatrace Vulnerability Feed расширен. Runtime Vulnerability Analytics (RVA) теперь проверяет более широкий набор вредоносных пакетов по отношению к компонентам, загруженным и выполняющимся в окружении, совместно с существующими данными об уязвимостях.

Записи о вредоносных пакетах используют ту же структуру, что и записи об уязвимостях, поэтому существующие дашборды, фильтры и рабочие процессы устранения продолжают работать.

* Заголовки начинаются с `Malicious code`, чтобы отличать их от известных уязвимостей.
* Каждая запись содержит `CWE-506` (Embedded Malicious Code).
* По умолчанию записи имеют критическую степень серьёзности с оценкой CVSS 4.0 равной 9.3 (вектор `AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N`).

Охват распространяется на те же шесть экосистем, что и Dynatrace Vulnerability Feed: Java, JavaScript, Python, Go, .NET и PHP.

Platform

### Блокировка приёма ненужных измерений метрик

Теперь можно остановить приём определённых измерений метрик с помощью нового списка **Metric dimension block list** в ![Settings](https://dt-cdn.net/images/settings-icon-256-38e1321b51.webp "Settings") **Settings** > **Metrics**. Ранее ненужные измерения метрик собирались автоматически без возможности их исключить. Это даёт прямой контроль над тем, какие измерения метрик поступают в окружение, позволяя исключить неиспользуемые данные и сосредоточить мониторинг на важном.

Нечаянного усечения данных при установке хранилища транзакций, Session Replay или файлов мобильных символов в значение `0` теперь можно избежать. Подсказка и всплывающее окно информируют о последствиях этой операции и предотвращают случайное внесение изменений.

Platform | OneAgent

### Новый параметр конфигурации для обнаружения логов в бинарном формате

Введён новый параметр конфигурации `BinaryDetectionMode`, позволяющий управлять тем, как Log Agent обрабатывает файлы с бинарным или неподдерживаемым кодированием в источнике логов (LGI).

Чтобы настроить этот параметр, перейдите в ![Settings](https://dt-cdn.net/images/settings-icon-256-38e1321b51.webp "Settings") **Settings** > **Log Monitoring** > **Advanced Settings** и задайте свойство **BinaryDetectionMode**.

По умолчанию весь источник логов помечается как бинарный и перестаёт обрабатываться. Для существующих развёртываний поведение не изменяется.

Platform | OneAgent

### Подзадачи потока логов zDC можно перезапускать во время выполнения

Введены две новые команды для отключения и подключения подзадач потока логов. Они полезны, если подзадача неожиданно завершила работу, но перезапускать весь zDC нежелательно.

* Для отключения обеих подзадач потока логов: `Modify ZDCJOB,LOG DETACH`.
* Для подключения обеих подзадач потока логов: `Modify ZDCJOB,LOG ATTACH`.

## Критические изменения

Infrastructure Observability

### Новейшая функциональность Dynatrace, связанная с ActiveGate, недоступна в классических окружениях Dynatrace

Модули ActiveGate, которые поддерживают исключительно классические страницы мониторинга и приложения Dynatrace, запрещены для ActiveGates, подключённых к окружениям Latest Dynatrace. Это затрагивает следующие модули:

* AWS monitoring
* Azure monitoring
* Cloud Foundry monitoring
* VMware monitoring
* Memory dumps
* Database insights

Полный актуальный обзор всех доступных модулей ActiveGate и поддерживаемых ими типов развёртывания см. в разделе [ActiveGate purposes and functionality](/managed/ingest-from/dynatrace-activegate/capabilities "Узнайте о возможностях и применении ActiveGate.").

Platform | Problems

### Закрытые проблемы больше не переоткрываются

Решённые закрытые проблемы остаются закрытыми даже после обнаружения связанных событий. При возникновении новых связанных событий Dynatrace Intelligence создаёт новую проблему. Это делает отслеживание проблем более предсказуемым и согласованным.

## Исправления и обслуживание

### Исправленные проблемы в данном выпуске

* Исправлена проблема, при которой все зоны управления окружения непреднамеренно удалялись, хотя должна была быть отменена только несохранённая конфигурация. (PS-47784)
* Экран **Deploy Dynatrace ActiveGate** теперь адаптирует имя файла и команды установки в соответствии с целевой версией ActiveGate. (MGD-13588)
* Улучшено применение контроля доступа для загрузок ActiveGate: ссылки на загрузку ActiveGate теперь требуют токена с областью `UnattendedInstall` или `ServiceApiProvider`. Существующие рабочие процессы в интерфейсе не затронуты. При использовании пользовательских скриптов, автоматизации или прямого доступа через API для загрузки ActiveGates убедитесь, что используемый токен содержит одну из требуемых областей. (MGD-12913)
* Изменено сообщение об ошибке, когда обновления кластера не могут быть запущены, так как не все узлы работают. (MGD-12678)
* Исправлена проблема, при которой записи таблицы **Explorer** для сервисов отображали некорректную статистику. В деталях сущности сервиса статистика отображалась корректно. (ICP-6867)

* Исправлена проблема с воспроизведением Session Replay, при которой шрифты страницы не загружались, если ответ поступал с задержкой. (DEM-29408)
